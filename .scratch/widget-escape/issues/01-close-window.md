# WIDGET-ESC-01 — Escape closes the widget

- Status: completed; owner: chat-widget worker; context: chat-widget.
- Goal: Pressing Escape while the chat iframe is open closes the entire widget window, not just the support menu, and returns focus to the launcher. Escape from the host launcher while the window is open should close it too.
- Allowed paths: `web/assets/loader.js`, `web/assets/widget-core.mjs`, `web/tests/**`, and this issue for worker evidence. Coordination files stay with the orchestrator.
- Contract: `docs/contracts/chat.md` embedding section. Any new iframe-to-parent control message must have an exact shape/version, validated parent origin and source; no guest data or capability crosses the boundary. Existing init/ready/resize behaviors stay intact.
- Invariants: no send, ticket, rating, or history mutation on close; no reload on reopen; keep keyboard focus accessible; no secret/credential/network change; preserve sandbox and CSP. One Escape should close even if the support menu is expanded. Other keys must not close the chat. Avoid changing report files or unrelated feature work.
- Acceptance: real trusted keyboard Escape inside the iframe (including when the email form/menu is open) and on the host launcher closes the window; launcher `aria-expanded` and label reflect closed state, focus returns to launcher, reopen retains conversation and entered draft; invalid-origin/source or malformed close messages are ignored. Existing menu tests updated for new behavior.
- Checks: `make format lint static unit contract` and affected browser integration; report evidence. Run `fuzz-smoke` if state transition rules warrant it per project testing contract.
- Dependency: existing widget and embedding contract; no backend change required. Blocker: none known. Next decision: orchestrator review of implementation and evidence.
