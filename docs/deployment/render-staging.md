# Render staging preparation — not a deployed service

This is a **limited public demo/pilot**, not an official university service or a production release. Jitihada is fictional, not an accredited institution. Nothing here authorizes account access, provisioning, a first deployment, migrations, content import or model requests. No hosted URL, live AI success, remote corpus or free-account eligibility has been verified.

`render.yaml` describes one Docker web service on **plan: free**, with no Render database, disk, addon, migration, seed, deploy hook or automatic Git deploy. It is a future operator input, not a safe command to execute now: creating a Blueprint can create resources and launch the first deployment even with `autoDeployTrigger: "off"`. Blueprint **Auto Sync** is a separate dashboard setting; turn it off for manual-only changes. Do not use a Deploy-to-Render button or trigger a sync as a validation step.

## Packaging and prerequisites

The multi-stage `Dockerfile` builds only the existing Go monolith (Go **1.26.3**, CGO disabled); widget and SQL assets are embedded by Go. No frontend build or project-wide tool installation is used. The runtime contains the compiled binary, Debian runtime files and CA certificates needed for Gemini/Turso HTTPS, runs as UID/GID 65532, and receives secrets only at runtime. Base OS tags and package repositories are mutable, not digest-locked reproducible inputs. Resolve/review image digests in a separately authorized release-hardening step if needed.

The default-deny `.dockerignore` admits only module manifests, the known Go source directories, SQL migrations and public embedded assets; tests, `.git`, `.env*`, database files, scratch, node dependencies and caches are excluded. Review newly added source/assets for credentials before any build; filename filtering cannot detect a secret deliberately placed in source. No source tree or build cache is copied into the final stage. A native cross-build is **not** a container build or container runtime test.

Render provides `PORT` (normally 10000). The Docker command requires a valid numeric port and explicit nonempty origins, exports `LISTEN_ADDR="0.0.0.0:$PORT"`, and execs `assistant serve`. It overrides any inherited loopback `LISTEN_ADDR`. TLS terminates at Render; the app's canonical origin must still be HTTPS. No startup migration or seeding is added. `/widget/widget.css` is the health check: it demonstrates HTTP/static serving only, **not database schema, approved content, AI availability or readiness**.

**Integration prerequisite:** the backend/widget owner's separately accepted change must implement `ASSISTANT_PUBLIC_DEMO=true`, visibly label the demo and disable email support on both server and widget. Merely setting this variable on the baseline does not implement that policy. Do not publish this baseline image. Coordinator must integrate both handoffs and independently verify the combined source revision first.

## Free-service, privacy and spend limitations

Render documents sleep after 15 idle minutes, roughly a minute to wake, 750 shared free instance hours/workspace/month, ephemeral files, possible restarts and no persistent disk on free web services. Free SMTP outbound ports 25/465/587 are blocked; this demo must not offer working email escalation. Do not create keep-alive/heartbeat requests to bypass sleep. Build minutes/bandwidth are quota-limited; paid supplementary usage is possible when a payment method exists. `plan: free` alone is **not a zero-bill guarantee**. Account eligibility remains an operator checkpoint; stop on card verification or billing prompts.

Turso currently advertises a free plan without a credit card and quotas, but that is not evidence for this account or an unlimited service. Do not enable overages. Quota exhaustion or provider rejection may make the demo unavailable; suspend/pause rather than upgrade. Track current quotas manually under later authorization. The app's single-process concurrency/rate controls reset on restart and do not bound account spend or prevent public abuse. Use only a narrow pilot; no production SLA, durable-backup guarantee or public-release readiness claim.

Questions, conversation history, ratings and any optional supplied context can persist remotely; inference sends bounded question/history and approved excerpts to the configured Gemini endpoint. Render, Turso and Google are separate processors. Do not submit personal, confidential or real student data. No automatic PII filtering, deletion schedule, GDPR compliance, provider non-training policy or specific provider retention period is verified here. Agree the pilot notice, retention/deletion procedure and provider terms **before** accepting participants; unresolved privacy/retention or spend controls block public acceptance. Memory-only browser access does not delete database history.

Keep operational logs to timestamps, revision, status and non-sensitive failure categories. Do not log transcripts, user comments/email, request bodies, Authorization headers, provider payloads or credentials. Do not enable HTTP/body debug logging. Avoid exporting logs/artifacts containing the database or credentials. Establish restricted operator access and an explicit retention review; do not assume free-tier logs are a durable audit record.

## Rollback and teardown — future authorized actions only

Record the previous **accepted combined source commit** and its schema compatibility before deployment. For an application regression, stop traffic and manually select/redeploy that accepted revision only after checking it supports the current schema and preserves demo/email-disable policy. The baseline `8410640e027c732a83dc35d354f8c4a56736be0e` is a source reference, **not** a public-demo-safe rollback target without the policy merge. Keep automatic Git deploys and Blueprint Auto Sync disabled. Redeploying old code does not roll back remote data/schema, restore deleted content or undo provider usage. Never drop tables, reverse migrations or restore/import a database without separate authority and backup review.

For teardown, first stop public traffic; under explicit resource-deletion authorization remove the service from Blueprint management and delete it in Render. Removing YAML or deleting a Blueprint alone does not delete its resources; leaving a resource defined can recreate it on sync. Separately revoke future provider/Turso tokens, remove repo integration permissions if no longer needed, and execute the approved remote data-retention/deletion plan. Do not delete a shared database or revoke shared credentials blindly. Confirm no paid resources or active automatic triggers remain without dumping secrets.
